# ABORT Review — tag v0.1.0 and release `develop` → `main`

**Decision under review:** Should `robot-accomplice/slop-ferret` be tagged **v0.1.0**, merged `develop` → `main`, published as a GitHub Release, and listed on the public roboticus.ai Sister Projects page as an open-source tool "from the same team"?

**Reversibility / blast radius:** **PARTIALLY IRREVERSIBLE, MEDIUM.** A tag can be deleted but not un-fetched; `go install` caches by module version and the Go module proxy retains what it has seen. Publication on roboticus.ai is a public statement of quality by association with magma, ghola, counterspy and architext. The tool writes into `~/.claude/` — another vendor's config tree — and creates command entries that determine which tools an AI agent is granted. No user data, no money, no migration.

**Date:** 2026-08-02 · **Reviewer:** ABORT gate, 5 independent red-team stations + operator reproduction of 4 findings · **Mechanical gate:** GREEN (`just ci`: gofmt, vet, golangci-lint 0 issues, `go test ./... -race`, coverage 83.7% against an 80% gate), 22 commits ahead of `main`, 0 tags.

---

## A — Premortem (assume it failed)

We tagged v0.1.0, the card went up on roboticus.ai, and it failed because the tool's headline output — a coverage fraction presented as the answer to *"was this repository actually audited?"* — turned out to be an uncorroborated restatement of whatever the auditing agent claimed. Someone pointed `ferret` at a repository they had reason to distrust, which is the only thing it is for, and that repository's `origin` URL wrote a file outside the records directory. Someone else ran a sweep that read nothing, and it wrote a durable record asserting two lexicon classes clean with an empty method, which the next sweep read and skipped. And through all of it the CI was green, the coverage was 83.7%, and the README said the tool existed to make exactly that misreport impossible.

**The one sentence that, said in review, would have stopped the ship:** *"You have never once run this against real magma output, and every fixture you tested against was written from your own belief about the contract."*

---

## B — Red Team Findings (five independent stations, verdicts verbatim)

1. **Attacker / Security — NO-GO.** `RepoKey` (`internal/gate/record.go:63-81`) returns the audited repository's `origin` URL unsanitised into `filepath.Join(root, key)` at `record.go:102`, giving any repo you point `ferret` at a directory-traversal `MkdirAll`+`WriteFile` primitive outside `~/.slop-ferret/` — demonstrated overwriting `~/.claude/settings.json` — which is disqualifying for a tool whose sole purpose is to be aimed at untrusted code.
2. **Worst-Case Customer — NO-GO.** `ferret install` non-deterministically links one of the two command entries and not the other (7/20 reproduced runs), leaving `/slop-ferret:report` resolvable while `/slop-ferret` is not — precisely the "allowed-tools never apply" safety defect the installer was written to eliminate, while `install.go:45` asserts no code path can produce it.
3. **Resource Auditor — NO-GO.** The headline artifact `coverage.repo` is an uncorroborated self-report driven to `100.0%` / `settled` / exit 0 with a hand-typed JSON having read nothing; and the `h_worklist` vocabulary measures 59% label precision and **0-of-6 recall on the files that produced every recorded finding**, including the ghola file the tool was built to catch.
4. **Future Maintainer — NO-GO.** The magma JSON seam — the tool's entire reason to exist — has never once been executed against real magma output in any test, and doing so for the first time reproduced three live defects in it (`semantic` fidelity mislabelling every Rust candidate, `limitations` silently discarded despite magma's contract naming this gate as its consumer, `plan.Contract` written but never validated).
5. **Domain / Integrity — NO-GO.** `VerifyAndRecord`/`WriteRecord` persist unvalidated `checked_clean` claims — empty method accepted — from a sweep that read 0 files and exited 3, and `SKILL.md:99-101` instructs the next sweep to skip that ground without checking `status`, so the persistence layer is itself a mechanism by which an unperformed audit reads as a completed one.

**Vote tally: 5 NO-GO, 0 GO-WITH-CONDITIONS, 0 GO.** No station dissented. The stations were blind to each other and converged from five unrelated angles.

### Root-cause clusters

- **A — "Nothing corroborates anything."** (I1, A1, I2, I3, I4, I5) Every layer that could check the layer below instead propagates it: the discharge is not checked against reality, the record is not checked against the discharge, the report is not checked against the record, and the next sweep trusts the record. **Leverage point:** break the laundering chain at the persistence boundary — the only place a claim becomes durable input to a future decision.
- **B — "The contract carries a signal and the consumer ignores it."** (M1) Dirty-map (`tree`), refusal (`rows: null`), `limitations`, `semantic`, `plan.Contract`. Two were fixed today; three are live. All five share one cause: **the seam has never been exercised against the real producer.** Leverage: one real-magma integration test.
- **C — "Prose describes behaviour the code lacks."** (P1, S3, M2, C2, X1) The class this tool exists to hunt, live in its own `internal/` and `cmd/`, because today's remediation was scoped to markdown.
- **D — "Write primitives escape their root."** (S1, S2) No containment assertion anywhere between a derived path and a filesystem call.
- **E — "The install is not atomic and misattributes its own damage."** (C1, C3) Content written before links, manifest written after; an aborted install then accuses the user of editing files ferret wrote.
- **F — "The ranking heuristic does not rank."** (V1) 59% precision, 0/6 recall on the files that actually produced findings.

### The one fix

**Cluster A is the highest-risk cluster, and the single change that neutralises it is: refuse to persist a record from a sweep that did not settle, and drop any `checked_clean` entry without a non-empty `method`.**

That one change breaks the chain by which an unperformed audit becomes durable, trusted input to a future audit. It does not make `read_paths` corroborated — nothing short of tool-side observation would — but it stops the tool converting an unverified claim into an artifact whose whole purpose is to be believed later.

**Necessary, not sufficient.** It does not touch S1, M1 or C1, each of which independently blocks.

### Acceptable risks (do not block, must be recorded)

- **S2 (decompression bound)** — the fetch path has no users today, and `SECURITY.md` already records that fetched assets are unverified. *Why deferred:* subset of a stated gap, no reachable trigger before a release exists.
- **C3 (Windows)** — real, but the honest remedy is to stop publishing a Windows binary until one has been run, which is a scope decision, not a fix. *Why deferred:* dropping a target is cheaper and more honest than claiming untested support.
- **I5 (record overwrite)** — data loss is confined to the operator's own store and is recoverable by re-sweeping. *Why deferred:* no third-party impact; needs a schema decision, not a patch.
- **C2 (magma acquisition)** — one README line. *Why deferred:* trivially fixable, blocks nothing structurally, and will be swept up by any of the above.

### Dealbreaker

**YES — three independent ones.**

1. **S1**, a filesystem-escape primitive driven by the artifact the tool is designed to point at things it distrusts.
2. **A1 + I1**, the tool's headline claim — that it makes "COMPLETE at 17 of 25" impossible to misreport — is false; it renders the same unverified claim as a percentage and then persists it for the next sweep to trust.
3. **M1**, the seam the product is built on has never been executed against its real producer, and the first time anyone did, it produced three live defects.

Any one of these blocks. Together they say the tool has not been shown to do the thing it exists to do.

# FINAL VERDICT: NO-GO

### Convertibility conditions

Blocked until enumerated conditions are met — not blocked forever.

1. **S1** — `RepoKey` output confined to a single safe path segment; assert the resolved directory is still under `recordsRoot()` before any `MkdirAll`; validate `pl.SHA` as `^[0-9a-f]{7,64}$` before it reaches a path. Adversarial tests for each; none exist today.
2. **M1** — an integration test that runs **real magma** over a fixture repo and asserts the full envelope is consumed: `semantic` in the fidelity table, `limitations` parsed and surfaced onto candidate bars, `plan.Contract` validated on read.
3. **I1** — `WriteRecord` refuses a sweep whose `status != "settled"`, and drops `checked_clean` entries lacking a non-empty `method`.
4. **A1 / I2 / I3 / I4** — the self-report limitation stated in `headline`, `ferret records`, and the report banner spec; `repo_note` corrected; `0/0` cannot settle; `pct` floors rather than rounds; waived count mandatory in the report banner.
5. **C1** — install becomes atomic: validate every link target and refuse before writing anything, or stage-and-swap the whole deployment; manifest written on the same path as the content.
6. **P1 / S3** — the prose-vs-code grep extended over `internal/` and `cmd/` and added to the release checklist; `gate.go:478` and `install.go:316` corrected; `SECURITY.md` corrected on the git surface and the `allowed-tools` blast radius.
7. **V1** — either move consequence ranking to sink-reachability in magma, **or** state plainly in the README that the vocabulary is a reading-order hint with measured 59% precision and no recall guarantee. The current framing oversells it.
8. **X1** — pin the constants' provenance to a committed fixture, or delete the instruction to re-measure, which is currently unfollowable.
9. **CHANGELOG** rewritten to describe what actually changed, including the six defects fixed after its last edit.

### Operator note — a defect in this review's own inputs

The entire five-repo campaign ran against **magma 0.1.0** while **magma 0.3.0** ("the contract release") sat built in the source tree. Two consequences:

- The **roboticus-rust** sweep concluded "Rust unsupported" when the truth was "the operator ran a stale binary". That record is wrong and should be re-run.
- The `semantic` fidelity and `limitations` findings existed the whole time and were invisible because the stale producer never emitted them.

Recorded here rather than quietly corrected, because it is the same failure the review is about: a conclusion drawn from an instrument nobody checked.
