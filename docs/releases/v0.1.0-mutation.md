# v0.1.0 — mutation triage

Pre-release mutation run (`gremlins unleash`) over the three packages that carry logic. Recorded
per the project rule: *survivors need triage, not a number; an untriaged efficacy percentage is
exactly the kind of figure this tool exists to distrust.*

## Runs

| Package | Coefficient | Killed | Lived | Not covered | Timed out | Efficacy |
|---|---|---|---|---|---|---|
| `internal/gate` | 20 | 215 | 38 | 49 | 0 | 84.98% |
| `internal/report` | 20 | 20 | 8 | 5 | 0 | 71.43% |
| `internal/install` | 20 | 23 | 0 | 10 | **64** | (invalid) |
| `internal/install` | 40 | 80 | 7 | 10 | 0 | 91.95% |

**The timed-out counts are machine- and load-dependent, not just for `internal/install`.** At
coefficient 20, install reports 64 mutants `timed out` — indistinguishable from survivors. Re-running
install at 40 resolves every one (0 timed out) and yields exactly the 7 survivors the handover
recorded, so they were slow, not infinite loops, and not real gaps. `internal/report` shows the same
effect under load: the 0-timed-out figure above held on one run but a concurrent re-run reported ~22
false timeouts at coefficient 20, resolving only at a much higher coefficient — the survivor set (8)
is stable, the timeout count is not. The justfile default of 20 is too tight on this host for both
packages; tracked as issue #21.

## This round's new guards — all killed

Every guard added while driving v0.1.0 was mutation-checked and killed, **except one equivalent
mutant**:

- `shaMatches` (gate.go) — killed, EXCEPT `gate.go:454` `if len(short) > len(long)`
  (`CONDITIONALS_BOUNDARY`, `>`→`>=`). **Equivalent:** the equal-length case returns at line 450, so
  line 454 is only reached when the lengths differ and the boundary is unreachable as a
  distinguishing case. Unkillable by construction; not a gap.
- `decodeStrict` + the plan/discharge unknown-field rejection (enumerate.go) — killed.
- `familiesActuallyRun` (report.go) — killed. The computed lexicon label
  `LexiconVer: pl.VocabProvenance["lexicon_version"]` is a plain map-lookup assignment with no
  operator for gremlins to mutate, so it does not show as a mutation *kill*; its behaviour is pinned
  by `TestFromSweepTakesTheLexiconLabelFromThePlan`, which goes red when the label is regressed to
  the authored source. Behaviourally bound, not mutation-killed.
- The struct-derived spec tests (`instructions`, discharge fields, git subcommands, release-dry
  platforms) — the const/format-string `+` operators they surround show as `NOT COVERED
  ARITHMETIC_BASE`; these are string concatenation in `const`/`Sprintf` and are non-viable /
  equivalent, not logic gaps.

## Pre-existing survivors — triaged

- **`internal/gate` (38 lived, 49 not-covered):** the 37 the handover already triaged (display
  assembly, a truncation cap, date extraction, unreachable defensive guards) plus the one equivalent
  at `gate.go:454` above. The `not-covered` set is dominated by `ARITHMETIC_BASE` on string
  concatenation in the `instructions` const and format strings — non-viable.
- **`internal/report` (8 lived):** the rate/denominator display (`report.go:110–112`), the
  zero-findings tell boundary (`report.go:119`, by design — see issue #19), and format-string
  concatenation (`150–152`). Display/by-design, not logic gaps.
- **`internal/install` (7 lived at coeff 40):** counters compared only against zero
  (`INCREMENT_DECREMENT`, equivalent), a truncation/bound and defensive guards. The one recorded
  real gap is `resolveRef`'s response validation — untested because it does unmockable network I/O;
  closing it needs dependency injection (tracked as a known gap, not a v0.1.0 blocker).
